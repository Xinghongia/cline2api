## 工作日志写作规范

**何时写**：里程碑完成、架构级改动、较大 bug 修复（含排查过程）、重要依赖引入、破坏性迁移。

**必含内容**：

1. **背景** — 为什么做（关联哪个里程碑/问题现象）
2. **改动范围** — 涉及的目录/文件/接口，尽量列全
3. **关键决策** — 选了什么方案、放弃了什么、为什么
4. **踩坑与修复** — 遇到什么错、怎么定位、怎么解决（这部分最有价值）
5. **验证方式** — 怎么确认改对了（测试/命令/手动步骤）

**风格**：面向"半年后回来看的自己"，写清楚来龙去脉，不写流水账。

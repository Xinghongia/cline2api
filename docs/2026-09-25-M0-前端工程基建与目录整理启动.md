## 关键决策

1. **antd 5 → 6 + React 18 → 19**：初版脚手架按 antd 5.22 写的，经查证 antd 6.0.0 已于 2025-11 发布稳定版（当前 6.5.x），原生支持 React 19，官方宣称 v5→v6 无需 codemod。趁只有骨架代码立即升级，实测**零代码改动**通过 tsc + vite build。注意：Ant Design **Pro**（Umi 脚手架）与 antd（组件库）版本号相互独立，本项目用的是组件库本体 + 自建 Vite 工程。
2. **旧 UI 兜底机制**：`frontend/dist` 只有 `.gitkeep` 占位时（未执行 npm build），`/admin/` 回退返回旧版 `adminHTML` 字符串——保证任何时刻 checkout 仓库都能 build & 运行，M1 对齐验收后才删除旧 UI。
3. **构建顺序契约**：go:embed 要求 dist 存在 → npm build 必须先于 go build（Dockerfile 阶段顺序、CI step 顺序、build.sh 前置检查三处共同保证）。

## 踩坑与修复

### 1. 测试顺序污染：TestHTTPTransportUsesHTTPSProxyFromEnvironment 全量跑 FAIL 单跑 PASS（提前从 M5 处理）

- **现象**：全量 `go test ./...` 该测试必挂，`-run` 单跑必过。
- **根因**：全局 `httpTransport.Proxy = clineOutboundProxy`，未配置应用内代理时回退 `clineEnvProxy = http.ProxyFromEnvironment`。stdlib 的 `ProxyFromEnvironment` 内部用 `sync.Once` **缓存首次调用时的环境变量快照**——全量跑时更早的测试触发过一次真实调用，缓存了无 HTTPS_PROXY 的环境；之后 `t.Setenv("HTTPS_PROXY", ...)` 再设置也不生效。原代码注释显示作者已意识到该坑（专门做了 `clineEnvProxy` 注入接缝），但默认值仍指向缓存版函数。
- **修复**：`clineEnvProxy` 默认实现改为 `httpproxy.FromEnvironment().ProxyFunc()`（`golang.org/x/net/http/httpproxy`，已是间接依赖，升为直接依赖），每次调用即时解析环境变量。单次开销远小于一次网络请求，语义与原版一致（含 NO_PROXY 处理），测试顺序从此无关。修复后全量测试**全绿**。

### 2. 仓库历史 gofmt 欠账

`gofmt -l` 发现 9 个文件有真实格式问题（`requireAdminAuth` 缩进错位、结构体字段未对齐、EOF 缺换行），系历史提交未跑 gofmt 所致。已全量格式化并**单独成提交**（`style:` 前缀），保持功能提交 diff 干净。

### 3. Windows 下重建 exe 需先停进程

`go build -o cline-proxy.exe` 覆盖正在运行的 exe 会失败（文件锁），先 `taskkill //F //IM cline-proxy.exe`。

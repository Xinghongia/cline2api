# 2026-09-25 M2：Go 目录重组——单包平铺到 cmd/ + internal/ 十二包

## 背景

M2 目标是把根目录 30+ 个平铺的 Go 文件拆成标准布局（`cmd/` 双入口 + `internal/` 分层包），**行为零变化**。方法：依赖序逐包搬移 + 编译器驱动修错 + 每步 `go test ./...` 全绿再进下一步。

## 最终结构

```
cmd/
├── cline-proxy/            # CLI 入口（原根 main.go，去掉 build tag）
└── cline-proxy-desktop/    # 桌面入口（原 desktop_main.go）+ resource_windows_amd64.syso
internal/
├── types/       # Account/Model/RequestLog/TokenUsage + ParseTokenUsage/MergeTokenUsage（纯函数）
├── apphome/     # resolveDataPath → apphome.ResolveDataPath
├── strutil/     # Truncate
├── randx/       # Intn（crypto/rand 驱动）
├── httpx/       # 全局 Transport/Client + PostForm/PostJSON/ReadBody + DialViaProxy/dialHTTPProxy
├── proxyconfig/ # .cline-config.json 的读写（Get/Set/Default）
├── pool/        # 账号池（State/Mu/Path 导出）+ RefreshClineToken/ParseExpiry
├── cline/       # auth.go、models_sync.go、cline_proxy.go（出口代理池）、capture.go
├── zen/         # zen.go、zen_proxy.go、compact.go（限流状态机、压缩）
├── providers/   # 提供商数据模型/CRUD/解析/冷却（执行逻辑留在 server）
├── chatmsg/     # SanitizeMessages/CleanMessages/GenToolUseID/HasToolUseBlocks/PassThroughKeys/MsgCount + Token 常量
├── reqlog/      # 请求日志存储（Load/Append/Finalize/List/Filter + 测试访问器）
└── server/      # HTTP 服务层：proxy.go、responses.go、admin.go、i18n.go、frontend_dist.go、version.go + 4 个集成测试文件
```

根目录不再有任何 .go 文件。

## 关键决策

1. **relay 与 admin 合并为 internal/server**（偏离原计划的偏离点）：admin 的 handleProviderTest 依赖 relay 的 callProvider/normalizeOpenAIResponse，relay 的 startProxy 又注册 admin 路由——双向依赖是客观存在的。强行拆分需要回调注入 + 导出大量符号，收益不抵成本。决策依据是"依赖实况"而非"教科书分层"。
2. **pool 的全局变量导出而非封装**：`pool`/`poolMu`/`poolPath` 改名 `State`/`Mu`/`Path` 直接导出。因为 relay/admin 大量持有 pool.Mu 锁来修改账号字段（recordTokenUsage 等），完整封装需要把这些逻辑全部搬进 pool——超出机械搬移范围。封装留待后续。
3. **解环手段**（按优先级）：
   - 纯函数下沉：ParseTokenUsage/MergeTokenUsage → types；Truncate → strutil；randIntn → randx；dialViaProxy/dialHTTPProxy → httpx；sanitizeMessages 系列 → chatmsg
   - 处理器归位：HandleAdminModelSync/handleProvider* 五件套从数据包移回 admin（admin API 层）
   - 执行逻辑归位：providers 的 CallProvider/handleProviderStreamResponse/callCustomProviderAPI 留在 server（与响应处理深度耦合）
   - 令牌刷新随池走：RefreshClineToken/ParseExpiry 进 pool（auth 依赖 pool.Add，反向放行会成环）
   - 钩子注入：httpx 的出口代理钩子由 cline 包 init() 直接赋值 Transport 字段
4. **vite 产物目录改为 internal/server/dist**：go:embed 路径不能上溯（`../`），产物必须位于包目录内。package.json build 脚本用 `node scripts/keep-dist.mjs`（.mjs + import.meta.url，跨平台）在构建后补回 .gitkeep。
5. **桌面端 build tag 消失**：CLI 与桌面拆成两个 main 包后，`//go:build !desktop`/`//go:build desktop` 分隔不再需要；build.sh 仍传 `production` tag（Wails 运行时约定）。

## 踩坑与修复（本里程碑的惨痛教训）

1. **Git Bash 的 grep 是 ugrep 别名，输出带 CRLF**：`sed -i ... $(grep -l ...)` 时文件名带 `\r` 全部 "can't read"。教训：文件列表用 `*.go` 通配，不用 grep 生成；后续多处用 `perl -pi -e` 配负向前瞻替代。
2. **sed 词边界替换会误伤**（本里程碑反复踩）：
   - 函数定义被改：`func resolveDataPath` → `func apphome.ResolveDataPath`（语法错误）
   - 结构体字段被改：`Model string` → `types.Model string`
   - 字段访问被改：`reqLog.Model` → `reqLog.types.Model`（用 `\.types\.` 模式二次修复）
   - 复合字面量键被改：`Model:` → `types.Model:`
   - **字符串字面量被改**（最危险，编译器不报错）：CLI 文案 "Account added to pool" 变成 "types.Account added to pool.State"。用 grep 定位含限定符的字符串行逐行修复。
   - 包名与局部变量冲突：getAllModels 的局部变量 `zen` 与导入包 zen 冲突 → 局部改名 zenList。
   - perl 负向前瞻 `(?!\.)` 保护了限定引用，但也保护了**变量的字段访问**（`pool.CurrentIdx` 漏改）——需要事后用 `grep -oE "pool\.[A-Za-z]+" | sort -u` 与已知符号集比对，找出漏网。
3. **删除函数时行号错位**：靠 sed 行号删除函数体两次切坏文件（auth.go 的孤儿 `}`、models_sync 丢闭括号、free_model_test 缩进错乱）。教训：**函数级搬移用 awk 提取 + 验证边界，删除后立即 go build 确认**；文本修复用 Read+Edit 精确替换而非盲改行号。
4. **goimports 在语法错误文件上静默跳过**：修完语法后必须重跑 goimports，否则出现 "undefined: xxx"（实为缺 import）。
5. **vite emptyOutDir 删占位**：M0 已处理（.gitkeep 自动补回），outDir 迁移后脚本路径也要跟着改（脚本里的相对路径以脚本文件位置为基准，`../` 差一层）。
